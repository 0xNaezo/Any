## 0. Три вывода, которые определяют канал

1. **Узкое место — не данные и не деньги на стек, а (а) квалификация и (б) ручной труд персонализации.**
   Кандидатов с запасом: только бесплатные источники дают **≈195 запусков/день** (ось 2), из них детектируется как no-code/AI-билдер **≈10–18 %** (ось 3) — т.е. десятки кандидатов в день при потребности 2–5 писем. Но сквозная квалификация (билдер × конкретная находка × реальный бизнес) по модели = **0.1–6.3 %** (ось 7, разброс ×63, точных данных нет) — это слабейшее звено. Стек стоит **$1–11/мес** бесплатно-минимально или **$45–122/мес** платно (ось 7) — не ограничитель. Ограничитель — **≈30 мин ручного исследования на контакт → 20–50 ч/мес** на 40–100 контактов (ось 7).

2. **Юридически «ядро» (Product Hunt) — самый проблемный источник, а «расширение» (Show HN) — самый чистый.**
   PH API **прямо запрещает коммерческое использование** и ToS запрещает скрейпинг; контакты мейкеров в API замаскированы (`[REDACTED]`) — для лидогенерации без письменного разрешения PH использовать нельзя (ось 1). Зато **HN Algolia API официально открыт, бесплатен и ToS-чист** (ось 2). Вывод для дизайна: автоматический сбор строить на Show HN / Uneed / TinyLaunch, а PH трогать только через публичный Atom-фид (серая зона) или по разрешению PH.

3. **Сам канал cold email по основателям легален не везде, и ряд инструментов его прямо запрещает.**
   - **Германия и Австрия:** cold B2B без предварительного согласия **запрещён** (UWG §7(2) Nr.2; TKG §174(3)) → этих получателей исключать (ось 6).
   - **GitHub AUP:** нельзя использовать данные сервиса «for the purposes of sending unsolicited emails» — формально запрещает брать email из GitHub для холодных писем (ось 5).
   - **ESP с прямым запретом cold:** Resend, Postmark, Amazon SES, Mailgun, Twilio SendGrid, Brevo (ось 6) → отправлять только из обычного ящика Google Workspace / Microsoft 365 (серая зона, не прямой запрет).
   - **GDPR Art. 14/21:** в первом же письме к получателю в ЕС — уведомление об источнике/основании и явное право возражения (ось 6).
   - Эти ограничения не убивают канал (US допустим по opt-out; FR/UK-юрлица — при условиях), но **жёстко задают: фильтр по стране получателя + аккуратный выбор источника контакта + ручной ящик**.

## 2. По шагам воронки

### Шаг 1. Найти запуск (оси 1–2)

**ЧТО и ОТКУДА (бесплатно, топ-источники):**
- **Show HN через Algolia HN Search API** (`hn.algolia.com/api/v1/search_by_date?tags=show_hn`) — без ключа, лимит 10 000 req/ч/IP; ~**124 запуска/день**, 97 % с URL (35.5 % ведут на GitHub). Поля: title, url, author, points, comments, время. Самый дев-ориентированный поток. `showstories` Firebase — НЕ весь поток (порог по очкам), использовать Algolia.
- **Uneed** официальный REST/MCP (`mcp.uneed.best/v1/launches`) — без ключа, ~**17–39/день**, в записи **URL сайта + соцссылки** (X/LinkedIn/GitHub), запрета скрейпинга в ToS нет.
- **TinyLaunch** — недельные архивы + JSON-LD `sameAs`=сайт, ~**46/день**; при желании нулевого ToS-риска замена — **Smol Launch** (офиц. API, 120 req/мин).
- Прочие бесплатные: PeerPush (нужен ключ), dev.to `#showdev` (~72/день, но это посты), Launch HN (~2–3/нед, только YC).

**УСЛОВИЯ (критично):**
- **Product Hunt:** единственный машинный список без токена — публичный **Atom-фид** `/feed` (50 записей, без пагинации, кэш 30 с; `published`≠день запуска; мейкеров/голосов/email нет). Сайт продукта — через редирект `/r/p/{id}?app_id=339` (robots разрешает именно этот путь). **API v2 бесплатен, но доки прямо: «must not be used for commercial purposes»**; ToS запрещает «crawls/scrapes»; контакты мейкеров `[REDACTED]`. Легальный путь к коммерции — письмо на **hello@producthunt.com** (цены/условия — нет данных). HTML PH закрыт Cloudflare для датацентровых IP.
- **Запрещают автосбор / платно:** Indie Hackers, TAAFT, G2, Reddit (коммерч.), Launch YC, Lobsters.

**ОТДАЧА:** суммарно топ-3 бесплатных ≈ **195 кандидатов/день** до дедупликации и фильтров; PH featured ≈ 25/день, доля AI среди топ-10 ≈ 67 %. При потребности 2–5 писем/день **объём — не ограничение**.

> **Важная сшивка с осью 3:** билдер по хосту URL почти не виден (0 из 11 168 Show HN URL на lovable/bolt/v0/bubble; vercel.app 1.4 %). Значит шаг 2a делается **по содержимому страницы**, а не по списку запусков.

### Шаг 2a. Слабый бэкенд — пассивный детект (ось 3)

**ЧТО определяется пассивно:** архитектура, **не дыра**. Видно билдер, хостинг и факт «браузер напрямую ходит в BaaS».
**Надёжные публичные маркеры:** платформенный домен (`*.lovable.app`, `*.bubbleapps.io`, `*.replit.app`, `*.bolt.host`, `*.base44.app`, `*.webflow.io`, `*.framer.app`, `*.flutterflow.app`); платформенные заголовки (Bubble `x-bubble-*`, Framer `server: Framer/…`); `meta generator` (Webflow, Framer, v0); бейджи (Lovable «Edit with Lovable», Bolt «Made in Bolt»); адрес BaaS в публичном бандле (`<ref>.supabase.co`, `firebaseConfig`). **Все убираются на платных планах и кастомных доменах.**

**Supabase/Firebase без мифов:** публичный `anon`/`sb_publishable_` и `firebaseConfig.apiKey` — **публичны по дизайну**, это не уязвимость; дыра (выключенный RLS/«Test mode») **пассивно не видна**. В письме формулировать как **архитектурное наблюдение** («браузер обращается к БД напрямую, защита держится на RLS»), а НЕ «ваша база открыта».

**ГРАНИЦА (этика/право, строго):**
- **Допустимо:** 1× `GET /` с подресурсами из HTML, favicon, DNS (A/CNAME/TXT), сертификат из того же TLS, `robots.txt`, локальный разбор уже опубликованного JS, платные/открытые базы третьих лиц (BuiltWith, StackScope, HTTP Archive).
- **Недопустимо:** перебор путей (`/.env`, `/admin`, `/api/*`), **любой вызов найденного API даже с публичным ключом**, использование найденных секретов, CORS/OPTIONS-пробы, обход Cloudflare/логина, `WhatWeb -a 3/4`, порт-сканы. Правовые якоря: политика CFAA DoJ (good-faith research ≠ лидогенерация), УК Украины ст. 361 + Постанова КМУ №497 (только по публичной оферте владельца), ToS SSL Labs/Wappalyzer/BuiltWith.

**Инструменты:** бесплатно и достаточно — открытые движки на одном ответе (**wappalyzergo, httpx `-td`, WhatWeb `-a 1`**) с правилами enthec (GPL-3.0; нет правил для Bolt/v0/Glide/FlutterFlow — писать свои). Платно: Wappalyzer lookup — только Business **$450/мес**; BuiltWith **$99/2000**; StackScope **£15/3000 запусков** (единственный готовый поток «запуски + стек», молодой, источник заинтересован). Security-чекеры: **SSL Labs нельзя** (ToS); securityheaders API закрыт (апр.2026); MDN Observatory — «active-light». Гигиену заголовков читать из самого `GET /`, внешний сервис не нужен (но это слабый дискриминатор — 45 % всех сайтов и так имеют оценку F).

**ОТДАЧА:** именованные AI-билдеры **7.3–8.6 %** запусков (StackScope, апр–июл 2026, источник заинтересован, ≈83 % с PH); с no-code и «клиент→BaaS» **≈10–18 %** [ОЦЕНКА] ≈ 2–5 из ~26 featured/день. Полнота fingerprint не измерена; для уровня «высокая» нужны ≥2 независимых класса сигналов. Доля с реальной проблемой RLS известна только из активных исследований (≈10–30 %, смещено) и **пассивно не подтверждается**.

### Шаг 2b. Реальный бизнес с деньгами (ось 4)

**ЧТО работает (дёшево, пассивно):**
- **Pricing-страница с ценами** — главный бесплатный «денежный» признак (**27 %** калибровочной выборки); «pricing + login/signup + Terms/Privacy» вместе (20 %) — это ещё и критерии мерчант-ревью Paddle.
- **Платёжный провайдер в публичном коде** (Stripe `js.stripe.com`/`pk_live_` **только в контексте Stripe**, Paddle `cdn.paddle.com`, Lemon Squeezy `lemon.js`, Polar) — сильный сигнал (пройден KYC), но редко виден статически (1/44; headless-рендер поднимет). Ловушка: `pk_live_` использует и Clerk — не только Stripe.
- **Метрики сторов:** iTunes Search/Lookup API (бесплатно, ~20 req/мин — рейтинги, даты релизов), Chrome Web Store (users/ratings) — для приложений/расширений.
- **TrustMRR** — единственный прямой бесплатный сигнал выручки (API, 10 req/мин), но база — самоотбор, поиска по домену нет, AUP запрещает «target a startup/founder» → для писем нужно письменное разрешение. *(единственный источник по теме — проверить при использовании.)*

**ЧТО НЕ работает на свежих запусках:** Tranco / CrUX / Majestic top-1M (**0/45** в выборке), Similarweb («No Data» при <5 000 визитов/мес), Crunchbase/PitchBook/Tracxn (платно, медиана Crunchbase API $20k/год; indie там нет). У bootstrapped-инди фандинга «обычно нет» — это норма, не красный флаг.

**УСЛОВИЯ:** **автосбор прямо запрещают** Crunchbase, LinkedIn (прецедент hiQ), Trustpilot, X (платный, $0.005/пост); данные Cloudflare Radar и производный Tranco — лицензия CC BY-NC (некоммерч.). Размер команды в LinkedIn смотреть **только человеком**.

**ОТДАЧА:** объём 2–5/день умещается во все бесплатные лимиты с запасом. Надёжного ground-truth по выручке нет (измерены частоты сигналов, не их точность); SPA-сайты (типично для Lovable/Bolt) статически «пусты» → без рендеринга охват занижен.

### Шаг 3. Найти контакт (ось 5)

**Лучший бесплатный путь (dev-аудитория):** сайт продукта (`/contact`, `/about`, `/privacy`, футер, mailto) → ссылки на GitHub/X/личный сайт с сайта и из профиля PH (смотреть **вручную**) → GitHub-профиль/коммиты, метаданные npm/PyPI → проверка **DNS MX** → при необходимости 2–3 кандидата через бесплатные пулы **Hunter (50/мес) + Prospeo (100) + Apollo (50)** и верификатор **Reoon (до 600/мес) / ZeroBounce (100) / MillionVerifier (500 trial)**. Бесплатных пулов хватает на объём 2–5/день (≈200–250 поисков + ≈700 проверок в месяц).

**УСЛОВИЯ (критично):**
- **GitHub AUP** прямо запрещает использовать данные сервиса «for the purposes of sending unsolicited emails to users» — санкция на аккаунт GitHub; формально рискованно даже для единичных писем. Держать как осознанный запасной путь с релевантным письмом по конкретному репозиторию.
- **LinkedIn и X** — автосбор запрещён ToS (CNIL оштрафовала KASPR на €240 000 за LinkedIn-контакты).
- **WHOIS/RDAP мёртв** (реальный email у ~1 %); **Clearbit/Breeze** email больше не ищут.
- **GDPR:** основание — legitimate interest (ст. 6(1)(f)) + уведомление ст. 14 в первом письме + право возражения ст. 21; EDPB считает LI недостаточным для email-маркетинга физлицам → завязано на страну (см. шаг 4).

**ОТДАЧА [ОЦЕНКА]:** валидный персональный email находится бесплатно для **≈30–40 %** dev-запусков и **≈15–25 %** no-code; платный finder поднимает до **≈45–55 % / 25–40 %**, но не выше доли доменов с MX (24 % доменов MX вообще не имеют). Замер на Show HN (n≈98): персональный email на сайте 18 %, role-based 35 %, ничего 45 %.

### Шаг 4. Отправить персональное письмо (ось 6)

**Инфра (рабочий вариант):** обычный ящик **Google Workspace Business Starter $7/мес** или **Microsoft 365 Business Basic $7/мес** на своём домене. Их политики запрещают «unsolicited mass/commercial email» (серая зона для 1:1; реальный триггер блокировки — жалобы, не сам факт).
**ESP, которые НЕЛЬЗЯ** (прямой запрет cold в AUP): **Resend, Postmark, Amazon SES, Mailgun, Twilio SendGrid, Brevo**. Cold-платформы (Instantly/Smartlead/lemlist) cold не запрещают, но на 2–5/день не нужны, а их пул-прогрев — риск.

**Обязательно по правилам провайдеров при нашем объёме:** SPF **или** DKIM, PTR, TLS, RFC 5322, жалобы <0.3 %. DMARC и one-click unsubscribe формально только для bulk (≥5 000/день), **но по факту для инбокса нужны SPF+DKIM+DMARC (p=none)** с выравниванием From — иначе спам/`5.7.26` (Gmail усиливает с ноября 2025).

**Обязательно по закону в каждом письме:** честные From/тема; пометка «предложение/реклама»; название отправителя + **физический адрес** + контакт; **рабочий отказ** (исполнить ≤10 раб. дней, жив ≥30 дней US / ≥60 дней CA); для EU/UK — **уведомление GDPR ст. 14 + явное право возражения ст. 21(4)**; для ЕС — **без трекинг-пикселей** без согласия.

**География (cold B2B, первое касание):** США — **допустимо** (opt-out, штраф до $53 088/письмо за нарушение); Канада — при «conspicuous publication» + релевантность (бремя на отправителе); UK — юрлица допустимо; Франция — при 3 условиях; **Германия и Австрия — НЕЛЬЗЯ** без согласия; прочие страны ЕС — нет данных (до юриста — не слать). Отправитель из Украины не снимает применимость права получателя (GDPR Art. 3(2)).

**Прогрев:** при 2–5/день **сервис-прогрев не нужен и рискован** (M3AAWG 11.2025, Spamhaus, Validity Heatwave блокирует домены с synthetic warming + cold outreach). Нужен только естественный рэмп без всплесков — при малом объёме получается сам.

**ОТДАЧА [ОЦЕНКА]:** inbox placement **≈80–90 %** (Gmail 85–95 %, Microsoft/Proofpoint 70–85 %). Главные риски: жалоба на крошечной выборке (1 на ~100 = 1 % > порога 0.3 %), отбивки/угаданные адреса, шаблонность, cold-платформы/пулы.

### Шаг 5. Follow-up (ось 6 + 7)

Оптимум **3–5 касаний** (Belkins; 4–7 по Instantly/Saleshandy — расхождение вендоров); фоллоу-апы дают **+40–59 %** ответов, но после 3-го растут отписки. Тот же ящик, простой секвенсер или вручную. На объёме 2–5/день секвенсер опционален (ось 7: Woodpecker ≈$14, Instantly $37.6–47, Smartlead $32.5–39 — всё «источник заинтересован»).

| Отправитель UA | Право получателя применяется (GDPR Art.3(2)) | ось 6 | Украинская юрисдикция не защищает |

**Нужен юрист (нет данных):** представитель в ЕС по GDPR Art. 27; страны ЕС кроме DE/AT/FR/UK; применимость CAN-SPAM/«physical address» к иностранному отправителю; разрешение PH и TrustMRR на использование.

## 6. Ожидаемая отдача (ось 7) и что убивает канал

**Воронка при 40–100 новых контактах/мес (2–5 писем/день, 3–4 касания):**
- База: **≈0.04–0.10 заказа/мес** (≈1 заказ на ~1 000 писем); верх: **≈0.22–0.55/мес** (≈1 на ~180); низ (угловой): почти ноль.
- Реалистично: **от «1 заказ за ~2 мес» до «1 заказ за ~2 года»** — это **медленное накопление**, не быстрый канал.
- Чтобы ≈1 заказ/мес: ~180 писем/мес при «верхних» конверсиях или ~1 000/мес при «базовых».
- Reply (человеческий, на контакт): **1.5–5.8 %**; малый объём + персонализация реально дают верхнюю корзину (×2–4 к массовым — подтверждено 3 вендорскими датасетами).
- **Все бенчмарки cold email — вендорские/агентские** («источник заинтересован»), расходятся до ×7.6; единственный нейтральный — порог Google 0.3 %.

**Что убивает канал (по убыванию подтверждённости):** 1) доставляемость/качество списка; 2) слабая/шаблонная персонализация (AI без правки: reply 4.1 % vs human 10.4 %); 3) нерелевантный таргетинг (основатели 0.57 % vs VP 0.32 %; 0–10 сотр. 0.72 % vs 10k+ 0.22 %); 4) недоверие/нет кейсов (36 % ЛПР; количественно нет данных — эффект ожидается на «звонок→заказ»); 5) перебор фоллоу-апов.

## 7. Главные «нет данных» — что стоит измерить пилотом (не домысливать)

1. **Доля прошедших квалификацию** (билдер × находка × бизнес): модель допускает **0.1–6.3 %** — разброс ×63, точных данных нет. Пилот в несколько сотен запусков сузит вилку на порядок (ось 7).
2. **Полнота (recall) детекта билдера** на реальных запусках — не измерена (ось 3).
3. **Реальный reply/positive в нашей нише** с оффером «письмо с находкой + фикс-прайс» — аналогов в бенчмарках нет (ось 7).
4. **Доля запусков с валидным email для no-code-аудитории** (измеряли на Show HN/dev) (ось 5).
5. **Ответ PH** на запрос коммерческого разрешения; **охват TrustMRR** и его цена Premium (оси 1, 4).
6. **Inbox placement на малом объёме** — независимых замеров нет, мерить seed-тестом (ось 6).
